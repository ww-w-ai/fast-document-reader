# FastDocReader — file map (what each file owns, and why)

`CLAUDE.md` carries the short map: which file owns what. This file is the long form — the
design decisions inside each one, and the invariant each decision answers to. Read the entry
for a file before you change its behaviour, then read the `INVARIANTS.md` entries it cites.

- `App/AppDelegate.swift` — menu bar built **in code** (no MainMenu.nib). Any standard shortcut or menu must be added here — including the tab jumps: ⌘1…⌘8 and ⌘9-is-the-LAST-tab live in a "Go to Tab" submenu of the Window menu, because in a code-built menu a key equivalent exists only if a menu item carries it. ⌥⌘←/→ use AppKit's own `NSWindow.selectPreviousTab(_:)`/`selectNextTab(_:)` and need no code of ours; ⌃⇥/⌃⇧⇥ were already AppKit's.
- `App/MarkdownDocument.swift` — `NSDocument`; render pipeline, presize + prerender, lazy media reconcile.
- `App/DocumentWindowController.swift` — text view, scroll, tabs, find, source-edit panel, keyboard nav, reading-line highlight, the sidebar split (`NSSplitViewController`) and every reflow path. `updateTextInset` owns the three passes that re-solve the document to a changed reading column — `reanchorFillMarginTabs`, `resizeTableColumns`, `resizeOfficeGraphics` — while `settleReadingColumn` is its geometry-only half for callers about to replace the storage (invariant 48).
- `Navigation/ReaderTextView.swift` — the reading cursor: key handling, unit navigation, gutter-click block select, reading-line band. `Navigation/TextNavigator.swift` — pure line/sentence/paragraph boundary math (no view). `Navigation/AnchorResolver.swift` — resolves an internal link's target fragment (bookmark or heading slug) to a scroll position; pure decision logic, no view, so a dead cross-reference resolving to "do nothing" is unit-testable without a window.
- `App/ExternalEditor.swift` — "Edit in <App>" for read-only office documents: finds a candidate editor by bundle identifier (never by path — an app that moves would otherwise become a dead button), remembered per format. Split into a pure, fully-tested half and an `NSWorkspace`/`Bundle` glue half verified by launching the app.
- `Render/MarkdownRenderer.swift` — CommonMark/GFM → `NSAttributedString`; also detects mermaid, ```` ```math ```` and `$$…$$` and turns them into web-block placeholders.
- `Render/WebBlock.swift` — the ONE place that knows there are two WebKit engines (`.mermaid`, `.math`); every measure/presize/reconcile pass iterates `enumerateWebBlocks`. `Render/WebBlockRenderer.swift` — WebKit → cached vector PDF, shared by both.
- `Render/PlainTextRenderer.swift` — non-markdown text (.txt/.csv/.log…) rendered VERBATIM, monospaced, one block per non-blank source line. `App/DocumentTypes.swift` — the single list of openable extensions; Info.plist mirrors it, and `DocumentTypeDeclarationTests` now fails when the two disagree in either direction (invariant 69).
- `Navigation/BlockEdit.swift` — pure source arithmetic for add/delete/move (no views), feeding `applySourceEdit`, the one path that changes the text. `App/OutlinePanel.swift` — the table-of-contents sidebar (LEFT `NSSplitViewItem` sidebar), built from the heading attributes the renderer already leaves behind. A document with no headings hides the button and collapses the panel, decided from the SPLIT VIEW's actual state rather than the controller's own `isOutlineVisible` flag — that flag records only what the user toggled in THIS window, while AppKit can restore a sidebar it saved from another one, which is how an empty 180pt panel ended up beside a document with no outline at all.
- `App/CommentPanel.swift` — the review-comments sidebar (a RIGHT `NSSplitViewItem` inspector, hidden by default, ⌥⌘C), mirroring `OutlinePanel`; lists `MarkdownDocument.officeComments`. The body highlight + number badge for each comment are drawn behind the glyphs (draw-time, gated by `ReaderTextView.commentsVisible`), never an inline attachment (invariant 38).
- `Render/Office/PageBandGeometry.swift` / `Render/PageBandLayoutDelegate.swift` / `Render/Office/PageBandPainter.swift` — the running header/footer, in its three halves (invariant 58): how tall the band at a page boundary is (the document's own two margins, never less than what we draw), the `NSLayoutManagerDelegate` that reserves it by pushing each page's first line down, and the draw-time painter that puts the header/footer in it with this page's live number. Nothing here touches the document string. The delegate also owns the ONE other thing that moves at a page boundary — a table that would otherwise run into the margin is moved whole to the next page (`pushWholeTable`, invariant 61), decided by `DocumentWindowController.settlePagedTables` from a layout that already happened.
- `Render/Office/PagePagination.swift` — where each SHEET is, in the text view's own coordinates — the rectangles printing puts on paper AND the ones the page outline draws on screen (invariants 59/60). Pure and view-free: one subtraction over numbers layout already holds, because the reader's page grid IS the paper. It also decides WHICH TABLES have to move so none of them prints in a margin (`tablesToPush`, invariant 61) — the same page arithmetic, judged by numbers rather than by looking at a printout.
- `App/PageViewOptions.swift` — the View menu's page toggles and the global `UserDefaults` preference behind them (invariant 60). The **outline is the master**: a header and a footer live in a page's own margins and a table is only broken at a page boundary, so `header`/`footer` are DERIVED from it rather than stored beside it, and hiding the pages hides them too. `MarkdownDocument.applyPageBand` is the single place that turns them into a band, called by both the render and `DocumentWindowController.reapplyPageBand`.
- `App/MarginNumbers.swift` — which unit a document's margin numbers use (`MarginNumberStore`), and the pure resolver turning a typed number back into a place in it (`MarginNumberNavigator`); `App/PageNumberDeskView.swift` and `App/JumpIndicatorView.swift` are the two overlays laid over the SCROLL view, where nothing can reach the layout manager (invariant 71). `App/ReaderScrollView.swift` — the pinch gesture: a paged document zooms the view, a text document previews the gesture and commits ONE rebuild at the size the fingers chose.
- `Render/RenderTheme.swift` — the BASE design system: type scale + rhythm tokens (line-height / spacing / indent ratios) + colour, inherited by three thin per-format branches `MarkdownStyle` / `OfficeStyle` / `PlainTextStyle`. The rhythm constants live here ONCE; renderers read tokens, never re-inline them (invariant 36) — including the two ABSOLUTE ones the rules use, `RenderTheme.tableBorderWidth` (an integer point, invariant 42) and `Palette.tableBorderFaint` (the perimeter stand-in of invariant 47, faint in the ALPHA, never in the width). `Render/Office/OfficeBlock.swift` — the format-neutral vocabulary all three readers map into: blocks, `Span`, `ParagraphFormat`, `TableFormat`, and `EdgeBorders`, whose `BorderDecl` gives an edge three states rather than two (invariant 47). `Render/Office/OfficeTextBuilder.swift` — the ONE format-neutral builder turning the office block vocabulary into typography, applying each block's resolved `ParagraphFormat`/`Span`/table geometry (invariant 37) and sizing every graphic through the single `graphicSize` a reflow re-uses (invariant 46). `Render/Office/HwpReader.swift` — the rhwp bridge: HWP/HWPX `Data` → rhwp's structured JSON (via the `CRhwpNative` FFI) → the SAME `OfficeReadResult` `DocxReader`/`OdtReader` return, pre-decoding every embedded image at read time into `OfficeReadResult.images` (the FFI parse handle can't survive to lazy reconcile). `Vendor/RhwpNative.xcframework` — the vendored prebuilt rhwp parser (Rust static library, arm64), statically linked and dead-stripped; rebuild it via `docs/BUILD-RHWP.md` — and note `Scripts/record-rhwp-source.sh` defaulted to the OTHER working checkout (`~/Documents/DEV/refs/rhwp`) while testing `[ -d "$RHWP/.git" ]`, which is a DIRECTORY in a plain clone and a FILE in a submodule: it therefore rejected `Vendor/rhwp-src`, fell through to the default, and recorded a build from the submodule as coming from a different commit. It now defaults to the submodule and tests `-e`. The Rust source is an unlinked fork checkout, and our own four commits are backed up IN THIS REPO as `vendor-patches/rhwp/` — **read that folder's README before touching the parser**: it records the base commit, the restore procedure, and why we are PINNED to 0.7.19 (upstream moved 7,345 commits / 45,014 source lines in ten days at ~110 merged PRs a day, so a needed fix is CHERRY-PICKED, never rebased onto `main`). `Vendor/RHWP-SOURCE.txt` names the commit the shipped `.a` was built from, coverage + known gaps in `docs/hwp-support-gaps.md`, full design in `docs/hwp-support-design.md`.
- `Render/TableBlockBuilder.swift` — turns a row/cell vocabulary (markdown GFM + office `Cell`s) into a REAL bordered `NSTextTable` (`GridTextTable`, an `NSTextTable` subclass carrying its column proportions), shared by both renderers, so cell text is real selectable/copyable/searchable document text (invariant 39); it also resolves each cell's four edges from the table's and its own declarations (invariant 47) and then resolves each BOUNDARY between two cells to a single drawer, with `collapsesBorders` off so the winner is ours rather than AppKit's (invariant 50). `build(width:)` takes the width to solve at — the real reading column for an office document, the `initialColumnWidth` placeholder only for markdown and for any build with no window yet — and `resizeTables(in:toWidth:)` re-solves every table's columns to absolute integer widths on each reflow, touching only cells that moved (invariant 48). `Render/SizedAttachmentCell.swift` — the attachment cell that OWNS its `reservedSize` so an `image==nil` medium keeps its space (invariant 1), used by images and formulas.
- `Render/Office/OfficeMarkdownSerializer.swift` — the `--extract` serializer: office block vocabulary → Markdown (pure `[OfficeBlock] -> String`, view-free), conservative mapping with a `<raw>` fallback for un-mappable tables (invariant 40). `App/HeadlessExtract.swift` — the `--extract` CLI itself (reads the file via the single `DocumentTypes.readOffice` dispatch → serializer → stdout); `App/main.swift` gates it BEFORE `NSApplication` so no GUI starts. `App/HeadlessPDF.swift` — the `--pdf` CLI, which CANNOT gate there because layout, fonts and printing are all AppKit: `main.swift` creates `NSApplication` with activation `.prohibited`, never installs `AppDelegate` (it would present the Open panel, invariant 43) and never enters the event loop, while `HeadlessPDF.waitForRenderToSettle` pumps the run loop by hand to drain the SAME asynchronous completion pipeline `render(into:)` schedules for the interactive reader (invariant 66).
- `QuickLook/QuickLookPreviewController.swift` — the Finder's space-bar preview (`QLPreviewingController`), built through the SAME door `--pdf` uses (`MarkdownDocument.read` → `makeWindowControllers()` → that controller's content view) so the preview cannot drift from the reader. It ships in `Contents/PlugIns/QuickLookPreview.appex`, assembled by `make-app.sh` from `Resources/QuickLookPreview-Info.plist` + `-.entitlements` (local/Developer ID) / `-mas.entitlements` (store), with a COPY of the app's own executable — see invariant 68 and `docs/02-planned/quick-look-extension-design.md` for the measured format-by-format outcome and the App Store's separate-App-ID requirement.
- `App/TextEncodingDetector.swift` — what a file's bytes actually are (BOM → strict UTF-8 → BOM-less UTF-16 → regional legacy → verified guess → Latin-1), and the bytes to write back in that same encoding.
- `Render/CodeHighlighter.swift` — single-pass native highlighter, 34 languages + aliases.
- `Cache/MermaidCache.swift` — content-addressed disk cache, keyed by (source + engine version) so the two engines never collide.
- `Resources/mermaid.min.js`, `Resources/katex.min.js`, `Resources/katex-inlined.min.css` (KaTeX fonts inlined as data: URIs — regenerate with `Scripts/build-katex-css.sh`). `Resources/Info.plist` — bundle config. `Scripts/make-app.sh` — build+bundle+ad-hoc sign.
