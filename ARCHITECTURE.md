# FastDocReader — file map (what each file owns, and why)

`CLAUDE.md` carries the short map: which file owns what. This file is the long form — the
design decisions inside each one, and the invariant each decision answers to. Read the entry
for a file before you change its behaviour, then read the `INVARIANTS.md` entries it cites.

- `App/AppDelegate.swift` — menu bar built **in code** (no MainMenu.nib). Any standard shortcut or menu must be added here — including the tab jumps: ⌘1…⌘8 and ⌘9-is-the-LAST-tab live in a "Go to Tab" submenu of the Window menu, because in a code-built menu a key equivalent exists only if a menu item carries it. ⌥⌘←/→ use AppKit's own `NSWindow.selectPreviousTab(_:)`/`selectNextTab(_:)` and need no code of ours; ⌃⇥/⌃⇧⇥ were already AppKit's.
- `App/MarkdownDocument.swift` — `NSDocument`; render pipeline, presize + prerender, lazy media reconcile.
- `App/DocumentWindowController.swift` — text view, scroll, tabs, find, source-edit panel, keyboard nav, reading-line highlight, the sidebar split (`NSSplitViewController`) and every reflow path. `updateTextInset` owns the three passes that re-solve the document to a changed reading column — `reanchorFillMarginTabs`, `resizeTableColumns`, `resizeOfficeGraphics` — while `settleReadingColumn` is its geometry-only half for callers about to replace the storage (invariant 48).
- `Navigation/ReaderTextView.swift` — the reading cursor: key handling, unit navigation, gutter-click block select, reading-line band. `Navigation/TextNavigator.swift` — pure line/sentence/paragraph boundary math (no view). `Navigation/AnchorResolver.swift` — resolves an internal link's target fragment (bookmark or heading slug) to a scroll position; pure decision logic, no view, so a dead cross-reference resolving to "do nothing" is unit-testable without a window.
- `App/ExternalEditor.swift` — "Edit in <App>" for read-only office documents: finds a candidate editor by bundle identifier (never by path — an app that moves would otherwise become a dead button), remembered per format. Split into a pure, fully-tested half and an `NSWorkspace`/`Bundle` glue half verified by launching the app.
- `Render/MarkdownRenderer.swift` — CommonMark/GFM → `NSAttributedString`; also detects mermaid, ```` ```math ```` and `$$…$$` and turns them into web-block placeholders.
- `Render/WebBlock.swift` — the ONE place that knows there are two WebKit engines (`.mermaid`, `.math`); every measure/presize/reconcile pass iterates `enumerateWebBlocks`. `Render/WebBlockRenderer.swift` — WebKit → cached vector PDF, shared by both.
- `Render/PlainTextRenderer.swift` — non-markdown text (.txt/.csv/.log…) rendered VERBATIM, monospaced, one block per non-blank source line. `App/DocumentTypes.swift` — the single list of openable extensions; Info.plist mirrors it, and `DocumentTypeDeclarationTests` now fails when the two disagree in either direction (invariant 69).
- `Navigation/BlockEdit.swift` — pure source arithmetic for add/delete/move (no views), feeding `applySourceEdit`, the one path that changes the text. `App/OutlinePanel.swift` — the table-of-contents sidebar (LEFT `NSSplitViewItem` sidebar), built from the heading attributes the renderer already leaves behind. A document with no headings hides the button and collapses the panel, decided from the SPLIT VIEW's actual state rather than the controller's own `isOutlineVisible` flag — that flag records only what the user toggled in THIS window, while AppKit can restore a sidebar it saved from another one, which is how an empty 180pt panel ended up beside a document with no outline at all.
- `App/CommentPanel.swift` — the review-comments sidebar (a RIGHT `NSSplitViewItem` inspector, hidden by default, ⌥⌘C), mirroring `OutlinePanel`; lists `MarkdownDocument.officeComments`. The body highlight + number badge for each comment are drawn behind the glyphs (draw-time, gated by `ReaderTextView.commentsVisible`), never an inline attachment (invariant 38).
- `Render/Office/PageBandGeometry.swift` / `Render/PageBandLayoutDelegate.swift` / `Render/Office/PageBandPainter.swift` — the running header/footer, in its three halves (invariant 58): how tall the band at a page boundary is (the document's own two margins, never less than what we draw), the `NSLayoutManagerDelegate` that reserves it by pushing each page's first line down, and the draw-time painter that puts the header/footer in it with this page's live number. Nothing here touches the document string. The delegate also owns the ONE other thing that moves at a page boundary — a table that would otherwise run into the margin is moved whole to the next page (`pushWholeTable`, invariant 61), decided by `DocumentWindowController.settlePagedTables` from a layout that already happened.
- `Render/Office/PagePagination.swift` — where each SHEET is, in the text view's own coordinates — the rectangles printing puts on paper AND the ones the page outline draws on screen (invariants 59/60). Pure and view-free: one subtraction over numbers layout already holds, because the reader's page grid IS the paper. It also decides WHICH TABLES have to move so none of them prints in a margin (`tablesToPush`, invariant 61) — the same page arithmetic, judged by numbers rather than by looking at a printout.
- `Render/Office/MasterPagePainter.swift` — the 바탕쪽 (master page): the running title, the tab down the outer edge, the full-page artwork and the PAGE NUMBER a Korean document pins to the sheet itself (invariant 78). Decides only WHERE on a sheet each object goes — it takes the sheet rectangles `PagePagination` already computed and adds the object's own paper coordinates, so it reserves nothing, measures nothing and lays out nothing. It is not a second `PageBandPainter` and shares only that file's page-field substitution, because the number in a master text box is the same `MDAttr.pageNumberField` span a running header carries. Not gated on drawing to screen: a printout without the document's own page number is missing part of the document.
- `App/PageViewOptions.swift` — the View menu's page toggles and the global `UserDefaults` preference behind them (invariant 60). The **outline is the master**: a header and a footer live in a page's own margins and a table is only broken at a page boundary, so `header`/`footer` are DERIVED from it rather than stored beside it, and hiding the pages hides them too. `MarkdownDocument.applyPageBand` is the single place that turns them into a band, called by both the render and `DocumentWindowController.reapplyPageBand`.
- `App/MarginNumbers.swift` — which unit a document's margin numbers use (`MarginNumberStore`), and the pure resolver turning a typed number back into a place in it (`MarginNumberNavigator`); `App/PageNumberDeskView.swift` and `App/JumpIndicatorView.swift` are the two overlays laid over the SCROLL view, where nothing can reach the layout manager (invariant 71). `App/ReaderScrollView.swift` — the pinch gesture: a paged document zooms the view, a text document previews the gesture and commits ONE rebuild at the size the fingers chose.
- `Render/RenderTheme.swift` — the BASE design system: type scale + rhythm tokens (line-height / spacing / indent ratios) + colour, inherited by three thin per-format branches `MarkdownStyle` / `OfficeStyle` / `PlainTextStyle`. The rhythm constants live here ONCE; renderers read tokens, never re-inline them (invariant 36) — including the two ABSOLUTE ones the rules use, `RenderTheme.tableBorderWidth` (an integer point, invariant 42) and `Palette.tableBorderFaint` (the perimeter stand-in of invariant 47, faint in the ALPHA, never in the width). `Render/Office/OfficeBlock.swift` — the format-neutral vocabulary every office document arrives in: blocks, `Span`, `ParagraphFormat`, `TableFormat`, and `EdgeBorders`, whose `BorderDecl` gives an edge three states rather than two (invariant 47). `Render/Office/RustEngine.swift` + `Vendor/FastdocEngine.xcframework` — **what actually reads a document.** Every build links the engine and there is no second configuration (S9): `DocumentTypes.readOffice` hands it the bytes and the extension and throws if it cannot read them, with nothing behind it. The engine hands the host its canonical `RenderTree` and nothing else (schema-v5 JSON was deleted 2026-09-05, invariant 172): `Render/Office/RenderTreeWire.swift` is the `Decodable` mirror of the `EnvelopeV1` wire, read from the SAME parse handle through `fastdoc_office_tree_json`, and `Render/Office/RenderTreeOfficeAdapter.swift` turns it into `OfficeReadResult` — the tree census accepts 669 of 669 real documents, and a docx/odt's pictures, which live in their own archive, reach the host on demand through that handle rather than inside the tree (invariant 115). `Tests/FastDocReaderTests/OfficeDifferentialHarnessTests.swift` is the harness that reads a real document through BOTH the oracle readers and this door and diffs the two (invariant 171). `DocxReader.swift` / `OdtReader.swift` / `HwpReader.swift` are still here and still under test as the ORACLE the engine is checked against, which is the one job they keep; `RustEngineBridgeTests.testNoProductionSourceCallsASwiftOfficeReader` fails the suite if a production file calls one (invariant 112). `Render/Office/OfficeTextBuilder.swift` — the ONE format-neutral builder turning the office block vocabulary into typography, applying each block's resolved `ParagraphFormat`/`Span`/table geometry (invariant 37) and sizing every graphic through the single `graphicSize` a reflow re-uses (invariant 46). `Render/Office/HwpReader.swift` — the reference rhwp bridge: HWP/HWPX `Data` → rhwp's structured JSON (via the `CRhwpNative` FFI) → the SAME `OfficeReadResult` `DocxReader`/`OdtReader` return, pre-decoding every embedded image at read time into `OfficeReadResult.images` (the FFI parse handle can't survive to lazy reconcile). The engine's own HWP path is a port of this file and is what the app runs; this one is the oracle it is compared against. `Vendor/RhwpNative.xcframework` — the vendored prebuilt rhwp parser (Rust static library, arm64), statically linked and dead-stripped; rebuild it via `docs/BUILD-RHWP.md` — and note `Scripts/record-rhwp-source.sh` defaulted to the OTHER working checkout (`~/Documents/DEV/refs/rhwp`) while testing `[ -d "$RHWP/.git" ]`, which is a DIRECTORY in a plain clone and a FILE in a submodule: it therefore rejected `Vendor/rhwp-src`, fell through to the default, and recorded a build from the submodule as coming from a different commit. It now defaults to the submodule and tests `-e`. The Rust source is an unlinked fork checkout, and our own four commits are backed up IN THIS REPO as `vendor-patches/rhwp/` — **read that folder's README before touching the parser**: it records the base commit, the restore procedure, and why we are PINNED to 0.7.19 (upstream moved 7,345 commits / 45,014 source lines in ten days at ~110 merged PRs a day, so a needed fix is CHERRY-PICKED, never rebased onto `main`). `Vendor/RHWP-SOURCE.txt` names the commit the shipped `.a` was built from, coverage + known gaps in `docs/hwp-support-gaps.md`, full design in `docs/hwp-support-design.md`.
- `Render/TableBlockBuilder.swift` — turns a row/cell vocabulary (markdown GFM + office `Cell`s) into a REAL bordered `NSTextTable` (`GridTextTable`, an `NSTextTable` subclass carrying its column proportions), shared by both renderers, so cell text is real selectable/copyable/searchable document text (invariant 39); it also resolves each cell's four edges from the table's and its own declarations (invariant 47) and then resolves each BOUNDARY between two cells to a single drawer, with `collapsesBorders` off so the winner is ours rather than AppKit's (invariant 50). `build(width:)` takes the width to solve at — the real reading column for an office document, the `initialColumnWidth` placeholder only for markdown and for any build with no window yet — and `resizeTables(in:toWidth:)` re-solves every table's columns to absolute integer widths on each reflow, touching only cells that moved (invariant 48). `Render/SizedAttachmentCell.swift` — the attachment cell that OWNS its `reservedSize` so an `image==nil` medium keeps its space (invariant 1), used by images and formulas.
- `Render/Office/OfficeMarkdownSerializer.swift` — the `--extract` serializer: office block vocabulary → Markdown (pure `[OfficeBlock] -> String`, view-free), conservative mapping with a `<raw>` fallback for un-mappable tables (invariant 40). `App/HeadlessExtract.swift` — the `--extract` CLI itself (reads the file via the single `DocumentTypes.readOffice` dispatch, so the ENGINE reads it, then this Swift serializer writes it → stdout). That split is why the engine's own `--extract` and the app's can be compared at all: `extract_matches_swift.rs` drives both over a real corpus, and against the last build that shipped the Swift readers it was 566 of 574 byte-identical with 0 differing and 8 refused by both (invariant 116 — that baseline binary cannot be rebuilt from this branch); `App/main.swift` gates it BEFORE `NSApplication` so no GUI starts. `App/HeadlessPDF.swift` — the `--pdf` CLI, which CANNOT gate there because layout, fonts and printing are all AppKit: `main.swift` creates `NSApplication` with activation `.prohibited`, never installs `AppDelegate` (it would present the Open panel, invariant 43) and never enters the event loop, while `HeadlessPDF.waitForRenderToSettle` pumps the run loop by hand to drain the SAME asynchronous completion pipeline `render(into:)` schedules for the interactive reader (invariant 66).
- `QuickLook/QuickLookPreviewController.swift` — the Finder's space-bar preview (`QLPreviewingController`), built through the SAME door `--pdf` uses (`MarkdownDocument.read` → `makeWindowControllers()` → that controller's content view) so the preview cannot drift from the reader. It ships in `Contents/PlugIns/QuickLookPreview.appex`, assembled by `make-app.sh` from `Resources/QuickLookPreview-Info.plist` + `-.entitlements` (local/Developer ID) / `-mas.entitlements` (store), with a COPY of the app's own executable — see invariant 68 and `docs/02-planned/quick-look-extension-design.md` for the measured format-by-format outcome and the App Store's separate-App-ID requirement.
- `App/DefaultAppClaim.swift` — becoming what the Finder opens a kind of file with, owned in ONE place because two doors reach it (the App menu's alert and step 2 of the first-run guide) and a second copy of the family list or of the read-back check is how the two would come to disagree. Claims are offered, never taken: an app that makes itself the handler on its own is hijacking a system-wide setting, which the App Store rejects. Three things are load-bearing. (a) **One tick per FAMILY, not per extension** — nine checkboxes is a form to fill in rather than a choice, so the list is four groups whose members are the distinct system types that family spans (`.md` and `.markdown` are ONE type, so one member covers both). (b) **What is OPENED is deliberately wider than what is CLAIMED**: macOS 14 confirms every claim with its own dialog, per TYPE, and they STACK — carrying `.docm`/`.dotx`/`.dotm`/`.tsv`/`.log` took all four families from six system dialogs to twelve, so those five are opened but not claimed (⌘I in the Finder still binds them per file). `testClaimingEverythingCostsSevenSystemDialogs` pins the count, because adding one plausible-looking member adds a dialog nobody sees until it ships. (c) **Success is read BACK, never trusted** — `isDefault` re-asks Launch Services after the claim, and the outcome names any family macOS refused, SORTED (a bare `Set` would list them differently on each run). `DefaultAppPicker` is the tick list both doors share; it takes the width its host gives it (the alert needs 420, the guide passes its own content width) and is frame-based because an `NSAlert` sizes an accessory view from `frame` and never lays it out. Invariant 69 has the measured behaviour of both APIs, including that the OLD `LSSetDefaultRoleHandlerForContentType` fails SILENTLY where the new one prompts.
- `App/WelcomeWindow.swift` — the first-run guide, walked in two steps: what the app is, then the default-app claim. Two steps rather than one screen, because the claim is the thing a new reader does not know to look for — installing the app changed nothing they could see, `.md` still opened elsewhere. **The tick that suppresses the guide lives on step 2**, so closing at step 1 writes nothing and the guide is due again next launch; that is the whole enforcement, with no trapping and no disabled close box (`testLeavingAtStepOneDoesNotCountAsHavingSeenIt`). `WelcomeStore.showsOnLaunch` reads an ABSENT key as "show", because `UserDefaults.bool(forKey:)` answers `false` for a key nobody wrote — which would hide the guide from the only reader it exists for. Shown from `AppDelegate` once the launch has settled either way (a document opened, or the Open panel dismissed with nothing) and reopenable forever from Help ▸ Welcome. Two layout rules earned by looking at it: a row's width constraint is activated only AFTER the row is in its stack (`no common ancestor` is a crash on every open, not a blemish — a test caught it), and every point's body is ONE line at this width, since four same-sized paragraphs wrapping to two or three lines read as a grey wall rather than four points.
- `App/TextEncodingDetector.swift` — what a file's bytes actually are (BOM → strict UTF-8 → BOM-less UTF-16 → regional legacy → verified guess → Latin-1), and the bytes to write back in that same encoding.
- `Render/CodeHighlighter.swift` — single-pass native highlighter, 34 languages + aliases.
- `Cache/MermaidCache.swift` — content-addressed disk cache, keyed by (source + engine version) so the two engines never collide.
- `Resources/mermaid.min.js`, `Resources/katex.min.js`, `Resources/katex-inlined.min.css` (KaTeX fonts inlined as data: URIs — regenerate with `Scripts/build-katex-css.sh`). `Resources/Info.plist` — bundle config. `Scripts/make-app.sh` — build+bundle+ad-hoc sign.

## `hosts/` — the other hosts of the same engine

- `hosts/avalonia/FastDoc.Avalonia/` — the Windows/Linux host (.NET 9 + Avalonia), and the directory that decides **what a non-Apple host does with a `RenderTree` that carries no boxes.** It shares exactly ONE thing with the macOS app: the tree — read through the same `fastdoc_office_open` → `fastdoc_office_tree_json` → `fastdoc_office_close` handle, decoded into `Model/RenderTreeEnvelope.cs` (the C# mirror of `EnvelopeV1`, invariant 172), and never a second projection. Layout is NOT shared: the tree is structure only, so this host places it with Avalonia's `TextLayout` the way the macOS host places it with TextKit — ADR 0002 (`docs/studio/adr/0002-host-layout-interim.md`), a transitional split that reverts to the engine the day the tree carries bounding boxes; the target state stays ADR 0001 (the engine owns font metrics). Nothing here is imported by the Swift app and nothing here reinterprets document structure. Its gates are `Scripts/host-gate.sh` and `Scripts/host-corpus-gate.sh`, its packaging is `Scripts/publish-host.sh` (invariants 175, 178, and the entries after 178). What each file decides:
  - `Program.cs` — the entry convention: a bare path argument is ALWAYS the GUI, and headless is only ever an explicit first flag (`--extract`, `--pdf <in> <out>`, `--sheets`, `--paint-probe`; invariant 178). Which process is primary: a named `Mutex` (`ai.ww-w.fastdoc.avalonia.mutex`) decides, and a second launch forwards its path over a named pipe opened with `PipeOptions.CurrentUserOnly` on both ends, then exits. What a missing engine looks like: `HandleEngineMissing` — exit code 2 in headless mode, an error window instead of the reader in the GUI (`EngineMissingDetail`). The `FMD_AVALONIA_*` environment flags live here and nowhere else: `FMD_AVALONIA_DEBUG=1` is the ONLY way a headless error prints a stack trace or this machine's absolute paths, `FMD_AVALONIA_GUI_EXIT_IMMEDIATELY=1` is the gate's GUI-entry smoke, `FMD_AVALONIA_REPEAT=N` reopens one document N times in one process, `FMD_AVALONIA_PIPE_PROBE` drives the single-instance pipe with no window on either side; `FMD_AVALONIA_PDF_TRACE=1` is read by `SkiaPageCanvas` and names the first page an image downsample lands on.
  - `Native/FastdocEngine.cs` — the P/Invoke surface, byte-matched to the C header, and the ONE place that resolves the engine library, in this order: `FASTDOC_ENGINE_LIB` if set (a path that does not exist is an error, not a fallback), else `runtimes/<rid>/native/<libname>` beside the managed assembly, else a loud failure naming every path tried. `Native/EngineErrorText.cs` — `Humanize`, the single point where an engine error kind (`invalidArchive`, `hwpReadFailed`, `panic`, …) becomes the sentence a person reads; no other file words an engine error.
  - `Model/RenderTreeEnvelope.cs` — the wire mirror; every field the host consumes is declared here and nowhere else.
  - `Rendering/RenderTreeLoader.cs` — one `OfficeDocumentHandle` per open document, disposed exactly once, and `RunDisposingOnThrow`: a handle that `fastdoc_office_open`'d never leaks past a deserialization throw. The lazy image path (`ImageBytes`) depends on that handle staying alive for the document's lifetime.
  - `Rendering/FlowDocumentView.cs` — flow mode, the default. Virtualised: estimated heights corrected as blocks reach the screen (invariant 174); a bounded LRU of built `TextLayout`s (capacity 200); a `Parallel.For` prewarm of the visible range plus a directional prefetch of the next 24 blocks off the UI thread, staged behind a backpressure cap; a layout generation token (`Interlocked`) bumped on every `SetTree`/zoom so a late worker cannot write document A's layout under document B's index; the rule that anything a worker thread touches is immutable (`ImmutableSolidColorBrush`, never `TextDecoration`); keyboard scrolling (arrows, PageUp/Down, Space, Home/End) through the SAME `ScrollByPixels` the wheel uses; theme brushes re-resolved on `ActualThemeVariantChanged`. `FlowDocumentBuilder` turns the tree into `FlowBlock`s — the block-emission rules `Paging/PageGeometry.cs` must mirror exactly.
  - `Rendering/TableGridRenderer.cs` — the ONE measurement of a table's rows (span occupancy, per-edge borders, shading), shared by drawing, page layout and settle.
  - `Rendering/ImageBlockRenderer.cs` — decodes on demand: hwp/hwpx via `fastdoc_office_image_base64` on the live handle, docx/odt from the source archive by `sourceKey` (the split of invariant 115), and refuses any zip entry over 200 MB (`MaxImageEntryBytes`).
  - `Printing/IPageCanvas.cs` — the ONE draw path with two surfaces: `AvaloniaPageCanvas` paints the screen's `DrawingContext`, `SkiaPageCanvas` paints an `SKDocument` page. `PdfExporter.cs` is the single door GUI Export PDF and headless `--pdf` share (invariant 66): text is vector — real glyph runs against the bundled Noto Sans KR, embedded once — and pictures follow three rules in `SkiaPageCanvas.ResolveImage`: original bytes embedded as-is when they are already JPEG/PNG and small enough, otherwise downsampled to the placed size and re-encoded (JPEG quality 85 without alpha, PNG with), cached by source-byte hash across pages so a repeated picture is embedded once.
  - `Paging/` — page mode, NOT the default: `TextMeasurerPort` installs the measurer and font provider before any `fastdoc_office_open`; `PageGeometry` reads paper and break markers; `PageLayout` places whole text lines and drives up to eight settle rounds; `TableSettle` mirrors `laidOutTables()`; `PageModePainter` draws only the lines of the page being painted, and when the surface is a `SkiaPageCanvas` it is a single-page export call keyed by `CurrentPageNumber`. Structurally complete, not yet accurate — sheet counts still miss the macOS `--pdf` count, and invariant 176 records what has to exist before the next attempt.
  - `Open/` — `OpenService` (file dialog, drop, the supported-extension list) and `RecentFiles` (ten entries, JSON on disk). `PathComparisonPolicy` decides when two path strings are the same document: `OrdinalIgnoreCase` on Windows and macOS, `Ordinal` on Linux, used by recents and reading positions alike.
  - `Reading/ReadingPosition.cs` — block index + fraction within it + zoom, keyed by path|size|mtime, so a position survives a zoom or a window-width change and a rewritten file gets a fresh one. Restored zoom FIRST, then position — the other order lets the zoom push the position away.
  - `Fonts/FontSetup.cs` — `WithBundledKoreanFallback()`, registered on EVERY `AppBuilder` the process constructs (invariant 177). Bundles `Assets/Fonts/NotoSansKR-Regular.ttf` (the full KR-region subset, TrueType outlines so PDF export embeds it as a real font) as the fallback for Hangul syllables and compatibility jamo, Hanja (CJK Unified Ideographs, Extension A, compatibility ideographs) and box-drawing shapes.
- `hosts/avalonia/FastDoc.Avalonia.Tests/` — the xunit half of the gate (67 test cases); the PDF tests run the built host as a subprocess, because a real `Window` cannot be created on an xunit worker thread and `Dispatcher.UIThread.Invoke` deadlocks under `SetupWithoutStarting()`.
- `hosts/avalonia/installers/` — `linux/` (`.desktop` + MIME for hwp/hwpx, `install.sh`/`uninstall.sh`) and `windows/` (`register.ps1`/`unregister.ps1`, HKCU only). Neither makes FastDoc the default app: Windows hash-protects `UserChoice`, and on Linux it stays the user's choice. Written on macOS and not yet run on either target.
- `Scripts/host-gate.sh` — the host's gate: Release build → xunit → three headless `--extract` opens against the real engine, one per family → the no-args GUI-entry smoke → the same `--extract` in a Linux container with no display server (invariant 175). `Scripts/host-corpus-gate.sh` — the real-document crash gate: every docx/odt/hwp/hwpx under the given directories through `--extract` and `--paint-probe`, 120 s per document, recording exit code and timing but never document text. `Scripts/publish-host.sh` — the ONLY publish that ships the engine: a self-contained `dotnet publish` per RID (win-x64, win-arm64, linux-x64, linux-arm64) with the matching engine library copied into `runtimes/<rid>/native/`, and `verify_rid` fails the run when that library is absent or under 1 MB instead of passing silently. The engine libraries come from `Scripts/build-engine-xplat.sh`; its win-arm64 target is cross-compiled with llvm-mingw (`$LLVM_MINGW_DIR`) and links the unwinder statically, refusing a DLL that imports `libunwind.dll` (invariant 206).
